# 监控与错误追踪配置指南

本文档说明如何为 Hydrogen 商店接入错误追踪和结构化日志。

---

## 一、架构概览

```
错误/异常
  ↓
lib/error-tracking.ts (captureError)
  ├─ 有 SENTRY_DSN → 上报 Sentry (HTTP store endpoint)
  └─ 无 SENTRY_DSN → 降级为结构化日志
  ↓
lib/logger.ts (结构化 JSON 日志)
  ↓
console → Oxygen stdout/stderr
  ↓
Shopify Admin → Logs（自动收集）
```

**设计原则**：
- 零额外依赖（不装 SDK，用手动 HTTP 上报）
- 无 DSN 时优雅降级，不影响功能
- 所有日志统一 JSON 格式，便于聚合分析

---

## 二、结构化日志（内置，无需配置）

`lib/logger.ts` 提供统一日志接口，输出 JSON 行：

```json
{"level":"error","timestamp":"2026-09-16T10:00:00.000Z","message":"Draft order creation failed","context":{"company":"Acme"},"error":{"name":"Error","message":"..."}}
```

已在以下位置接入：
| 位置 | 日志内容 |
|------|---------|
| `entry.server.tsx` | SSR 渲染错误 |
| `server.ts` | 全局未捕获错误 |
| `root.tsx` ErrorBoundary | 路由错误边界 |
| `root.tsx` footer | Footer 查询失败（降级） |
| `quote.tsx` | Draft Order 创建失败 / 通知失败 |
| `products.$handle.tsx` | 推荐产品查询失败（降级） |
| `_index.tsx` | 推荐产品查询失败（降级） |
| `notifications.ts` | 通知发送失败 |

查看日志：**Shopify Admin → Settings → Logs**（Oxygen 自动收集 stdout/stderr）。

---

## 三、Sentry 集成（可选）

### 1. 创建 Sentry 项目

1. 注册/登录 [Sentry](https://sentry.io)
2. 创建新项目 → 平台选择 **JavaScript**
3. 复制 DSN（格式：`https://<public_key>@<host>/<project_id>`）

### 2. 配置环境变量

```bash
# .env 或 Oxygen 环境变量
SENTRY_DSN=https://<public_key>@o0.ingest.sentry.io/<project_id>
```

### 3. 效果

- 配置后，`captureError` 自动把错误上报到 Sentry
- 未配置时，错误只走结构化日志（Shopify Admin Logs）
- 上报失败也不会崩溃（fallback 到本地日志）

## 四、错误上报覆盖范围

| 错误类型 | 上报点 | 说明 |
|---------|--------|------|
| SSR 渲染错误 | `entry.server.tsx` onError | 组件渲染异常 |
| 路由 loader/action 错误 | `root.tsx` ErrorBoundary | 4xx/5xx |
| 全局未捕获错误 | `server.ts` catch | fetch handler 异常 |
| Draft Order 创建失败 | `quote.tsx` | B2B 核心路径 |
| 通知发送失败 | `notifications.ts` | 降级路径 |
| 查询降级失败 | 各路由 catch | 非致命错误 |

---

## 五、日志级别约定

| 级别 | 用途 | 示例 |
|------|------|------|
| `error` | 需要人工介入的错误 | Draft Order 创建失败、SSR 错误 |
| `warn` | 降级/可恢复的错误 | 推荐产品加载失败、通知失败 |
| `info` | 关键业务事件 | 可选的，如 Draft Order 创建成功 |
| `debug` | 开发调试 | 本地开发用 |

## 八、扩展建议

1. **接入 Shopify Admin Logs 之外的分析**：将 Oxygen 日志转发到 Datadog/New Relic
2. **添加性能监控**：核心路径计时（如 Draft Order 创建耗时）
3. **业务事件埋点**：用 `logger.info` 记录关键业务事件（Quote 创建、订单完成）
4. **告警规则**：在 Sentry 中配置错误率告警、关键路径告警
